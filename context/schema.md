# Schema / Data Structures / Contracts

## Opening line object (`L()` helper, `index.html`)
```js
L(id, name, description, result, isTrap, category, moves, explanations, baseMoves)
```
- `moves`: SAN strings from move 1.
- `explanations`: object keyed by move index (Ponziani: even/White; Hippo: odd/Black).
- `baseMoves` (optional): auto-play count. Ponziani default 5, Hippo default 4.
  **Tactics puzzles reuse this field for the real ply number the mistake happened at in
  an actual game (up to 105)** — `playBaseMoves()` in `index.html` branches on
  `currentLine.opening==='tactics'` to skip the per-move animation for these.
- `ALL_LINES` = `PONZIANI_LINES` (opening:'ponziani', playerColor:'w') +
  `HIPPO_LINES` (opening:'hippo', playerColor:'b', flexible:true) + `TACTICS_PUZZLES`
  (opening:'tactics', from `tactics-puzzles.js` if present).

## Diagnostic cache (`.chesscom-diagnostic-cache.json`, gitignored)
Written by `test/chesscom-diagnostic.js`, read by `--report-only` and by
`test/build-tactics-puzzles.js`.
```
{
  username, months, dateRangeLabel, generatedAt, gamesScanned, failedCount,
  moveRecords: [{
    gameId, moveNumber, phase, cat ('blunder'|'missed-win'|null), dropPawns,
    mateMissed, mateAllowed, secondsSpent,
    // only present when cat != null (flagged plies):
    plyIndex, evalBefore: {cp, mate}, evalAfter: {cp, mate}, correctMoveSan
  }],
  gameSummaries: [{ gameId, opponent, endTime, timeClass, url, userColor,
                     sanMoves, userWon, mistakeCount, clockLeftMinutes }],
  repertoire: { whiteGames, ponzianiReached, ponzianiOpponentAllowed,
                blackGames, hippoPlayed }
}
```
`evalBefore`/`evalAfter` are **White-perspective** `{cp, mate}` from Stockfish; use
`toUserPerspective()` (`test/lib/tactics-classifier.js`) to flip to the user's side.
`dropPawns` and the mate sentinel (`scoreToPawns()`: `mate` encoded as
`±(1000 - |mate|)`) are for internal ranking only — never display them raw to a human
(`describeSwing()` handles the human-readable text and deliberately avoids the sentinel
leaking through). A record is only correctly excluded from "material drop" reporting
when **both** `mateAllowed` and `mateMissed` are accurately set — see the 9 Sep 2026 bug
in `context/insights.md`.

## `tactics-puzzles.js` (committed, NOT gitignored — served statically like `index.html`)
Generated by `test/build-tactics-puzzles.js` from the diagnostic cache via
`test/lib/puzzle-selection.js` (fixed quotas: `mate`/`catastrophic`/`common`, ~5 each,
per-game cap 2) and `test/lib/tactics-classifier.js`'s `buildPuzzle()`. Puzzle ids are
stable (`tactics-<gameId>-ply<plyIndex>`) so localStorage spaced-repetition progress
survives a rebuild for any puzzle that stays selected.

## chess.com API usage (`test/lib/chesscom-fetch.js`)
`getRecentGames(username, months)` — `months` counts **chess.com archive months**, not
calendar days; `--months 1` early in a month returns a near-empty archive. No auth. Game
objects carry `white.rating`/`black.rating` (post-game rating for that side) and full
PGN with `[%clk H:MM:SS]` tags parsed by `test/lib/diagnostic-analysis.js`.
